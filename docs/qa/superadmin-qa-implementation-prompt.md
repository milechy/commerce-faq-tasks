4. notes の「検証コマンド」を全部実行し、結果を出力ごと確認する
5. feature branch を切って PR を出す
6. Asana タスクにコメントで PR URL と、検証コマンドの結果サマリを書く

## リポジトリの規律
- main へ直コミット禁止。test-only の変更でも feature branch + PR。
- admin-ui/src 配下を触る PR は Tier S です。Mergify の auto-merge 対象外で
  hkobayashi の手動マージが必要なので、「auto-merge 待ち」と報告しないでください。
- コミット対象は明示的に git add してください。`git add -A` / `git add .` は使わないでください。
  この作業ツリーには**別レーンの未コミット変更**（package.json / pnpm-lock.yaml /
  src/api/admin/avatar/generationRoutes.test.ts）が混ざっています。PR に入れないでください。
- コメントは日本語。既存コードのコメント密度・命名・イディオムに合わせてください。
- 「なぜそうしたか」をコメントに残してください。何をしたかはコードが語るので書かなくて結構です。
- `[id].tsx` のような角括弧を含むパスをシェルで扱うときは必ずクォートしてください
  （zsh の glob が失敗して別ファイルを触る事故が過去にあります）。
- git stash はリポジトリ全体で共有されます。他レーンの WIP を巻き込むので、
  安易な `git stash pop` はしないでください。

## 検証について
- 各タスクの notes に検証コマンドが書いてあります。全部実行してください。
- 出力をパイプで握り潰さないでください（`| tail` で終了コードが隠れます）。
- テストが落ちたら「落ちた」と出力ごと報告してください。通ったことにしないでください。
- E2E を回す場合の注意:
  - storageState は約1時間で失効します。回す前に取り直してください。
  - ローカルの Playwright 同梱ブラウザ（chromium-1217）が未インストールです。
    `--project=superadmin-setup` は失敗します。
    superadmin プロジェクト自体は channel:'chrome'（システムChrome）で動くので、
    `--no-deps` を付けて回し、storageState は別途システムChromeで生成してください。
    生成には .env の TEST_SUPERADMIN_EMAIL / TEST_SUPERADMIN_PASSWORD を使います。
    （あるいは `npx playwright install chromium chromium-headless-shell` を完走させる）
  - E2E は本番を向きます（staging がありません）。ただし superadmin / copilot-tenant の
    両プロジェクトは page.route で全 /v1/admin/* をブラウザ内に閉じるため、
    本番DB・本番の集計指標・外部APIの従量課金には到達しません。
    ハーネスに新しいエンドポイントを足すときは、この性質を壊さないでください

## 補足: 並行実装するとき

同一フェーズ内の並行可タスク（T2-2/T2-3/T2-4 など）を同時に走らせる場合は、
**必ず worktree を分離**してください。同一チェックアウトで複数エージェントを動かすと
checkout が衝突します。node_modules は symlink で解決してください。
親セッション側も稼働中のチェックアウトでは作業しないでください。
