## 3. 本質的に解決すべき課題

### 課題A：「言った条件」と「実際に発火する条件」が別物で、その乖離が見えない

店主は自然文で指示する。LLM がそれを `trigger_pattern` に変換するが、実行時の判定は単純なキーワード部分一致（D1/D2）。下書きカードは「どんな時に」を人間向けの言葉で見せるだけで、実際に照合される文字列も、その網羅性も見せていない。

結果は **「登録したのに効かない」／「思ってもいない場面で変な答えを返す」**。指示ルール機能の存在価値そのものを毀損する。

### 課題B：承認と反映の対応が壊れている（D7・D8）

- 店主が **採用したのに反映されない**（D7）
- 店主が **承認していないのに反映される**（D8）

方向は逆だが根は同じで、「店主の意思」と「AIの振る舞い」の対応が切れている。**課題Aを直しても、ここが壊れている限り信用は回復しない。**

### 課題C：チャットの下書き・一覧が、ルールの実像より小さい

DBのルールは trigger / behavior / priority / is_active / テナント固有 vs `global` / `approved_responses` / `source` / `evidence` を持つ。チャットが見せるのは最初の2つだけ（D6）で、一覧も実質3〜4件で切れる（D3）。ルール同士の矛盾を検知する仕組みは存在せず、矛盾するルールは両方ともプロンプトに並んで注入される。

## 4. ユーザーが本当に得たい価値

指示ルールを触る店主が欲しいのはデータではなく、**「うちの店の言い方で、AIに接客させたい」** ——これだけ。分解すると:

1. **思ったとおりに答えるようになったと確信できること**（設定した ≠ 効いた）
2. **専門用語なしで指示できること**
3. **間違ったら安全に戻せること**
4. **今どう設定されているか、いつでも一望できること**

現状の実装は 2 を満たしているが、1 が課題A・Bで壊れ、4 が課題Cで欠けている。

## 7. 制約

### 7.1 3層の役割分担（この境界を破らない）

D7の実装で最も壊れやすい。**要件として先に固定する。**

| 層 | 役割 | 破ってはいけないこと |
|---|---|---|
| FAQ / 知識データ（RAG） | **事実の単一情報源** | 採用済み返答の事実がFAQと矛盾しても、事実はFAQを正とする |
| 指示ルール `expected_behavior` | **方針**（どう振る舞うか） | 事実の格納場所として使わせない（「保証は2年」はFAQへ誘導する） |
| `approved_responses` | **文体・言い回しの見本** | 逐語コピーを強制しない。事実を上書きさせない |

### 7.2 統合方針（新規ファイルを安易に作らない）

この方針はリポジトリの既存規約である。`copilot-preview/index.test.tsx` に
`it("テナントのIDでスコープした既存エンドポイントを叩く(新規APIを作らない)")` /
`it("PDFを落とすと旧UIと同じ既存エンドポイントへ送信が始まる(新APIを作らない)")`
が存在し、新規API作成の禁止がテストで機械的に守られている。同じ扱いを本件にも適用する。

| 変えるもの | 置き場所（ここ以外に作らない） |
|---|---|
| 一致判定 | `src/agent/tools/synthesisTool.ts` の `matchesTriggerPattern` |
| プロンプト注入（採用済み返答を含む） | `src/api/admin/tuning/tuningRulesRepository.ts` の `buildTuningPromptSection` |
| ツール定義 / 実行 | `toolDefinitions.ts` / `actionExecutor.ts` の該当 case |
| 確認ゲートの分類 | `src/api/admin/agent/confirmPolicy.ts`（新ツールは必ずどちらかの表へ。網羅性は `confirmPolicy.test.ts` が機械検出） |
| 自動生成ルールの `is_active` | `src/agent/judge/evaluationAnalyzer.ts` の INSERT に明示 |
| チャットUIのカード・チップ | `copilot-preview/index.tsx` の `type Card` ユニオン（`:76-84`）・既存チップ機構 |
| 2面共有ロジック | `admin-ui/src/lib/`（`chatSessionStore` / `useAgentChatTransport` / `tuningPriority` / `utils` が先例） |
| 優先度の段階変換 | `admin-ui/src/lib/tuningPriority.ts` のみ |
| 画面文言 | `admin-ui/src/i18n/ja.ts`（直書き禁止） |

**新規ファイルが許される条件（すべて満たす場合のみ）**

1. 2面、または `src` と `admin-ui` の双方が必要とする
2. 既存ファイルに置くと責務が明らかに混ざる（`index.tsx` は既に1570行）
3. **なぜ分けたか・単一化しない理由・既知の未解決事項を冒頭コメントに書ける**（`lib/chatSessionStore.ts` が基準）

**採用済み返答（D7）の注入制約**

- 注入点は `buildTuningPromptSection` のみ。`synthesisTool.ts` 側に文字列組み立てを書かない
- マッチしたルールに紐づく分だけを注入する（全ルールの採用文を常時注入しない）
- 取得は既存の `getActiveRulesForTenant` の戻り値を使い、**追加クエリを発行しない**

### 7.3 踏襲する既存パターン

| パターン | 実体 |
|---|---|
| suggest → 確認チップ → `confirmed=true` で save | `SUGGEST_TOOLS`（`index.tsx:513`）。`confirmed` 未設定では書かない |
| 確認は `__real:` 付き自然文の代理送信 | 専用APIを作らない |
| 未決定チップがあると操作ロック | `awaitingUserDecision → busy` |
| 実書き込みだけを進捗カウント | `REAL_WRITE_TOOLS`（`index.tsx:145-`）＋ `確認が必要` / `確認をスキップできません` を除外 |

| 旧UIへのリンクは別タブ固定 | 同一SPA内パスを `target` なしで開くと会話が消える |

## 8. テスト観点

**置き場所**: フロント単体 `copilot-preview/index.test.tsx`（`describe("CopilotPreviewPage — <観点>")` ＋ 日本語 `it()`）／共有ロジック `admin-ui/src/lib/<name>.test.ts`／サーバ `agentRoutes.test.ts`・`confirmPolicy.test.ts`／一致判定は synthesisTool 側／E2E `tests/e2e/qa-copilot-preview.spec.ts`・`qa-irregular-3roles.spec.ts`。**390px viewport を先に**。

### 8.1 正常系

| # | 観点 | 期待 |
|---|---|---|
| N1 | 自然文 → 下書き → 保存 | 下書きカード → 「保存して」 → 成功カード＋進捗バッジ+1 |
| N2 | 保存後の即時検証 | 同じ画面で「お客様がこう聞いたら」を試し、違えば直して再試行できる |
| N3 | 発火条件の提示 | どんな聞かれ方で発火するかが店主の言葉で示される |
| N4 | 一覧の一望 | 全件が有効/無効・優先度・出所つきで把握できる |
| N5 | 有効/無効の切替 | 無効化後は発火しない |
| N6 | 更新・削除 | 確認を挟んで動く。`delete` は high tier |
| N7 | テスト応答3案 → 採用 | 採用した文面が実際の応答に反映される |

## 10. 実装順序（依存関係から一意に決まる）

```text
G1 / G2 の方針決定
  ↓
① D8 是正（無断有効化を止める）              ← 最初。放置したまま他を作ると全部やり直し
  ↓
② D1/D2/D4 一致判定の是正 ＋ D3 打ち切りの解消  ← 「効かない」の根治。可視化の前提
  ↓
③ D7 採用済み返答の注入 ＋ D6 カードの整合      ← 「効いたか確認できる」ループの完成
  ↓
④ AI提案の承認導線・evidence 提示（AC29）
  ↓
⑤ 会話/ギャップからの作成、優先度編集、全件一覧（AC30）
  ↓
⑥ 新規テナント向け空状態・オンボーディング接続・旧UI導線の停止（AC31）
  ↓
⑦ メトリクス確認 → 旧UI閉鎖判断（AC32）
```

①②を飛ばして⑥から作ると、**「新UIで完結するが、効かないルールと勝手に有効化されたルールが並ぶ画面」** が完成する。順序は入れ替えられない。
