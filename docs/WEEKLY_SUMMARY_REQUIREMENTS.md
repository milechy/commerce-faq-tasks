## 1. 期間の定義（暦週）

- 今週 = 月曜00:00 JST 〜 現在（部分週）
- 前週比 = **先週の同一経過時間との比較**。理由: 部分週を先週まる1週間と比べると月曜午前は常に
  -90%台になり指標として使えない
- 先週の確定値は常に併記する（前週比の分母として既に取得済みのため追加クエリ不要）
- 週境界の計算は `src/lib/date/weekRange.ts` の純関数1本に集約する。SQL内に直書きしない
- 全テーブルの時刻カラムは `TIMESTAMPTZ`。`AT TIME ZONE 'Asia/Tokyo'` の往復変換が必須で、
  片側だけの変換は本番(サーバTZ=UTC想定)でのみ9時間ズレる。ローカルでは検出できない

## 2. 指標セット（`get_weekly_briefing` が返すもの）

| 指標 | 出典 | 備考 |
|---|---|---|
| 会話数・前週比 | `chat_sessions` | 既存 |
| 応答品質スコア | `conversation_evaluations` | 既存。0件時は行を省略 |
| 成約件数・金額 | `conversion_attributions` | 既存 |
| AIが答えられなかった質問（累計+上位3件） | `knowledge_gaps` | 既存 |
| FAQ総数・公開数・最終更新日 | `faq_docs` | **新規**。旧ダッシュボードStatCard代替（`LEGACY_UI_SUNSET.md:72`） |
| 承認待ちの指示ルール件数 | `tuning_rules`(`approved_at IS NULL AND rejected_at IS NULL`) | **新規**。`weeklyReportGenerator` からの唯一の引き継ぎ指標 |

**引き継がないもの**: バリアント比較(A/B)・新規反論パターン数 — super_admin/運用寄りの指標で
テナント管理者の語彙ではない。アポイントメント率 — 既存の成約指標に吸収。

## 3. 権威の分離（数値 vs 解釈）

- 数値・期間・件数は**サーバがカードとして直接描画**する。LLMの生成文を経由しない
- 状況の解釈と「次にやるべきこと」はLLMの文。**テストで固定しない**（必ず変わる前提）
- LLMの提案には R2C上の操作以外を出させない制約をシステムプロンプト側に持つ

---

## 4. 制約（実装時に守ること）

`CLAUDE.md` の「管理チャットUI (/copilot-preview) 規約」セクションが正。要約:

- 新規ツール・新規テーブル・新規エンドポイントを作らない。既存 case の拡張のみ
- `text`(自然文)を消して `card` だけを返さない — 既存パーサのフォールバック契約
- transport / 永続化 / IME を画面側に再実装しない
- メトリクスラベルにPII(質問本文等)を入れない
- 履歴ウィンドウ定数(20件/4000字)を個別機能都合で変えない
- `admin-ui/src` を含む変更は Tier S。auto-merge せず手動merge

## 5. テスト観点

**正常系**: 既存テナントでカテゴリクリック→カードに指標が揃う / 起動時ブリーフィングとカテゴリクリックで同一期間・同一数値 / チップ押下→既存ツールの確認フローに合流 / 390pxでカード崩れなし

**境界値**: 全指標0(新規テナント) / 前週0件(前週比の除算) / 評価0件(スコア省略) / FAQ総数0/20超 / 5クエリ中1本失敗(部分表示) / `tenantId`未特定 / **TZ=UTC実行時のJST週境界** / 月曜0時ちょうど・日曜23:59・年またぎ

**イレギュラー操作**: カテゴリ連打 / 応答待ち中の別カテゴリクリック(ロック) / 未使用チップを残したまま自由入力 / 次アクションを翌日押す(対象が処理済み) / 2タブ同時オープン / リロード直後(鮮度) / super_adminのテナント切替
